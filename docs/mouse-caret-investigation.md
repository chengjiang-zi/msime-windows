# 鼠标点击拼音：实验记录

目标是在应用输入框中点击未上屏拼音时，把编辑位置移动到点击处，并让下一次输入插入对应位置。当前功能尚未实现；本分支为实验分支，不应安装到日常电脑。

## 已观察到的现象

- 在一次性 Windows 测试机的 Rich Edit 控件中输入 `nihao`，用控件坐标确认点击命中第二个字符附近后，`WindowFromPoint` 返回的是个人版候选窗口，而非输入框。系统选区留在末尾，继续输入 `x` 得到 `nihaox`。普通 Edit 控件未能提供未上屏文字的坐标，因此其测试结果是无法判断。见[定位记录](https://github.com/chengjiang-zi/msime-windows/actions/runs/40758956595)。
- 临时裁去候选窗口顶部透明区域后，点击到达 Rich Edit，测试程序的 TSF 鼠标监听器收到字符边界 1；未修改的输入法仍将 `x` 加在末尾。该实验后续的候选词点击检查失败，原因待查，不能当成可发布修复。见[窗口区域实验](https://github.com/chengjiang-zi/msime-windows/actions/runs/40760887098)。
- 在未修改的基准包上，单击候选词可以正常上屏。测试只覆盖一次性机器上的默认皮肤和一个富文本控件，不能推断所有应用、皮肤或显示缩放的行为。
- 后续实验发现，测试编辑框保留鼠标捕获时，候选点击会被送回编辑框；仅在测试程序中释放捕获后，裁剪区域保留与重置两种情况下，候选点击均可上屏。见[捕获诊断](https://github.com/chengjiang-zi/msime-windows/actions/runs/40763518788)。这不代表输入法可以跨进程直接释放宿主的鼠标捕获。
- 另一实验让 TSF 监听器消费按下和松开事件，但在后续检查时编辑框仍持有捕获，实验未通过。见[事件消费实验](https://github.com/chengjiang-zi/msime-windows/actions/runs/40764231017)。还需要检查点击前、按下后、松开后的状态，确定捕获究竟何时产生。
- 分阶段点击显示编辑框在按下后获取捕获、松开后仍保持。带 `HTTRANSPARENT` 的跨进程实验也仍由候选窗口命中，点击没有到达编辑框；不能将其作为透明穿透方案。见[分阶段点击实验](https://github.com/chengjiang-zi/msime-windows/actions/runs/40765272388)。
- 只消费按下事件、放行松开事件也没有解除捕获，见[对照实验](https://github.com/chengjiang-zi/msime-windows/actions/runs/40765880658)。同一控件点击已上屏文字时，捕获在松开后正常释放；点击组合文字时则仍然保留，见[普通点击对照](https://github.com/chengjiang-zi/msime-windows/actions/runs/40766507453)。这只说明该控件在此测试场景的行为，不能推广到所有宿主。
- 跟踪测试编辑框的窗口消息发现，普通文本与组合文字两种情况下，编辑框都收到按下和松开；仅前者在松开期间释放捕获。见[宿主消息跟踪](https://github.com/chengjiang-zi/msime-windows/actions/runs/40767075428)。测试使用了临时裁剪和 TSF 监听器，因此尚不能单独归因于某一组件。
- 移除测试用 TSF 鼠标监听器后，保留临时窗口裁剪、点击组合文字，同一编辑框依然收到按下和松开却保留捕获。见[无监听器对照](https://github.com/chengjiang-zi/msime-windows/actions/runs/40767716041)。这排除了测试监听器是该场景的必要条件，但仍需在其他宿主和不同区域处理下验证。

## 需要解决的问题

1. 让候选窗口透明区域不遮挡应用，同时保留阴影、装饰、候选词点击、菜单、展开面板和多屏缩放行为。`HTTRANSPARENT` 在不同线程间的行为需要真实跨进程测试；窗口区域裁剪会影响显示，不能只看点击是否成功。
2. 将鼠标命中的显示位置映射回原始按键位置。双拼展开和分词符可能使两者不一一对应；已选中文前缀不应被当作可编辑拼音。本分支的纯映射策略只用于实验，尚未接入输入法。
3. 按焦点、组合会话和按键顺序同步 TSF 与后台光标。必须处理快速输入、切换窗口、无效映射、服务器掉线和旧回复，避免插错或丢失文字。
4. 在真实控件中验证点击、输入、退格、候选选择及取消，并检查无法获取点击位置的宿主能安全回退；再扩大到浏览器、高 DPI 和多显示器。

## 同步方案的约束

- 鼠标监听器只在当前上下文和组合范围有效时注册；组合结束、焦点改变、服务停用时解除注册。点击的显示字符边界必须先验证并映射到原始按键位置，无法可靠映射时保持现状。
- 后台更新须检查当前会话标识、焦点和原始输入是否仍与点击时一致，旧请求不能作用于新组合。更新后台位置、刷新候选与应用内选区应有清晰的确认和失败回退；确认前输入的按键必须有明确的保序处理，不能悄悄丢弃或插入错误位置。
- 不要假设鼠标回调中一定能同步取得文本写锁。[Windows 文档](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfcontext-requesteditsession)指出同步编辑会话可能失败，异步请求也可能在焦点或组合变化后才执行；必须重新验证上下文。
- 捕获由宿主窗口管理，诊断程序在自己的编辑线程里调用 `ReleaseCapture` 仅用于定位问题，不应据此在正式输入法中强行干预任意应用的捕获状态。
