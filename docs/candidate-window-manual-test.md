# 候选框稳定性：人工验证

在一次性 Windows 测试环境完成并存和卸载测试后，再进行以下检查。
不要在原版上直接安装本分支尚未验证的测试包。

## 准备

1. 启用个人版输入法，并打开候选词翻译；记录排列方式、皮肤、每页数量和屏幕缩放比例。
2. 用同一组拼音在原版和个人版分别录屏，比较候选框四个边缘及候选文本的位置。
3. 至少使用记事本和浏览器输入框；关闭并重新打开候选框，检查是否正常恢复自然尺寸。

## 场景

| 场景 | 检查 |
|---|---|
| 依次输入短、长拼音，并退格 | 同一次候选框显示期间，已达到的较大尺寸不应因文字缩短而反复收缩；长内容仍可扩大窗口。 |
| 译文异步显示、变长或变短 | 词条内容完整，候选框没有反复收缩；观察高亮和文本是否仍发生令人不适的位移。 |
| 候选页之间翻页 | 不丢候选、不改变选择顺序；确认保留空间可以接受。 |
| 输入框靠近屏幕四边 | 候选框不应越出可用区域；避让可能移动窗口，记录具体位置。 |
| 横排、竖排及展开面板 | 检查切换、展开与收起时无截断，尺寸不会被错误地沿用。 |
| 关闭候选词翻译 | 确认普通候选窗口沿用原有行为。 |
| 启用皮肤的 `fit_content` | 确认仍按皮肤设计收紧宽度；当前稳定逻辑不覆盖这个设置。 |
| 100%、125%、150%、200% 缩放及跨屏 | 检查窗口、文字、阴影和点击区域没有裁切、错位或越界。 |

## 已知限制

- 当前实现保留窗口在本次显示中达到过的较大尺寸，并不是固定尺寸：新内容更长时仍可能扩张。
- 保持尺寸可能留下空白；这是一项体验取舍，需要结合录屏和实际使用判断。
- 窗口是否跟随光标由现有“候选窗口跟随光标”设置控制；屏幕边缘避让仍可能移动窗口。
- 这些检查不能单凭代码或自动化布局测试替代，未实际执行时不得标记为通过。
